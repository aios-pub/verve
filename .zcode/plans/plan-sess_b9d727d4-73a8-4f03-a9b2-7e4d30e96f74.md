## 对比 Zed release workflow，补充 Verve 缺失的 release 支持

### 分析结果

对比 Zed 的 release workflow，Verve 当前缺少以下功能：

| 功能 | Zed ✅ | Verve 当前 | 补充方案 |
|------|--------|-----------|----------|
| Clippy 检查 | ✅ 三平台 | ❌ 无 | 新增 clippy job，`-D warnings` 阻止有警告发布 |
| 测试门禁 | ✅ bundle needs tests | ❌ 无 | 所有构建 job `needs: [clippy, tests]` |
| 多架构 | ✅ x86_64+aarch64 分开 | ⚠️ 仅 x86_64 | 新增 Linux aarch64 + Windows aarch64 构建 |
| SHA256 校验和 | ✅ | ❌ 无 | 每个产物生成 `.sha256` 文件 |
| Release Notes 自动生成 | ✅ 从 commit | ❌ 手写 | 新增 generate-notes job，从 git log 生成 changelog |
| Artifact 验证 | ✅ validate_release_assets | ❌ 无 | 新增 validate job，检查所有预期 asset 存在 |
| Concurrency 控制 | ✅ | ❌ 无 | 新增 `concurrency` 防止同 tag 重复发布 |
| 超时保护 | ✅ timeout-minutes | ❌ 无 | 每个 job 加 `timeout-minutes` |

(代码签名、Sentry、sccache、Slack 通知等 Zed 专有基础设施不实现)

### 实施计划

重写 `.github/workflows/release.yml`：

1. **meta job** — 提取版本号（不变）
2. **clippy job** — `cargo clippy --all-targets -- -D warnings`
3. **tests job** — `cargo test --lib --no-fail-fast`
4. **build-macos** — universal binary + .dmg + SHA256（`needs: [clippy, tests]`）
5. **build-linux-x86_64** — .deb + tarball + SHA256
6. **build-linux-aarch64** — cross 编译 aarch64-unknown-linux-gnu + tarball + SHA256
7. **build-windows-x86_64** — .msi + .zip + SHA256
8. **build-windows-aarch64** — aarch64-pc-windows-msvc + .zip + SHA256
9. **generate-notes** — 从 git log 生成 changelog
10. **release** — 创建 GitHub Release + latest.json
11. **validate** — 验证所有预期 asset 存在

同时更新 `.github/workflows/ci.yml` 增加 clippy + timeout-minutes。
