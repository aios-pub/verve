## 自动更新机制 + 手动更新按钮 + GitHub Actions 流水线

### 一、自动更新模块

**新增文件 `src/updater.rs`**：
- `UpdateInfo` 结构体：`version`, `release_url`, `download_url`（按平台匹配 asset）, `release_notes`
- `check_for_updates()` 异步函数：调用 GitHub API `https://api.github.com/repos/lijing/verve/releases/latest`，解析 JSON，对比 `CARGO_PKG_VERSION`（用 `semver` crate）
- `latest_release_manifest()` 函数：解析 `latest.json` 资产（CI 生成的更新清单），内含各平台下载 URL + 版本号
- `target_asset_name()` 函数：按 `cfg!(target_os)` 返回匹配的 asset 文件名（macOS→`.dmg`、Linux→`.deb`/`.tar.gz`、Windows→`.msi`）
- `open_release_in_browser()`：用 `cx.open_url()` 打开 GitHub release 页面

**修改 `src/lib.rs`**：新增 `pub mod updater;`

**修改 `Cargo.toml`**：新增依赖 `semver = "1"`

### 二、手动更新按钮（两处入口）

**入口 1 — 标题栏（始终可见）**：
- 修改 `src/ui/app.rs` 的 `render_title_bar()`，在右侧环境选择器旁新增一个 `RefreshCw` 图标按钮
- 平时点击 → 手动触发 `check_for_updates()`，按钮显示 loading 旋转动画
- 检查中 → 按钮禁用 + 图标旋转
- 检查完毕无更新 → `window.push_notification()` 提示「当前已是最新版本」
- 有新版本 → 按钮变为带红点的 `Download` 图标，点击打开浏览器下载

**入口 2 — 设置页「关于 / 检查更新」区域**：
- 修改 `src/ui/settings_window.rs` 通用设置页底部新增：
  - 显示当前版本号 `v{CARGO_PKG_VERSION}`
  - **「检查更新」按钮**（手动触发检查，检查中显示 loading 文案）
  - 有新版本时显示：新版本号 + release notes 摘要 + **「前往下载」按钮**（打开浏览器）
  - 无新版本时显示：「✓ 当前已是最新版本」
  - GitHub 仓库链接 `https://github.com/lijingrs/verve`

**入口 3 — 启动自动检查（静默）**：
- `VerveApp::new()` 末尾 `cx.spawn` 异步检查，查到新版本存入 `update_info` + `cx.notify()`
- 不弹通知，仅标题栏按钮变红点提示（避免每次启动打扰）

### 三、VerveApp 状态字段

`src/ui/app.rs` 新增：
```rust
/// 最新版本信息（有新版本时 Some）。
pub update_info: Option<updater::UpdateInfo>,
/// 是否正在检查更新（驱动按钮 loading 状态）。
pub update_checking: bool,
/// 上次手动检查结果（用于设置页显示）。
pub update_check_result: Option<UpdateCheckResult>,
```
`UpdateCheckResult` 枚举：`UpToDate` | `UpdateAvailable(UpdateInfo)` | `Error(String)`

### 四、更新清单文件（CI 生成）

CI 流水线在每次 release 时生成 `latest.json` 上传为 release asset：
```json
{
  "version": "0.2.0",
  "url": "https://github.com/lijingrs/verve/releases/tag/v0.2.0",
  "notes": "Release notes...",
  "platforms": {
    "macos": { "url": "...Verve-0.2.0.dmg" },
    "linux": { "url": "...verve-0.2.0-amd64.deb" },
    "windows": { "url": "...Verve-0.2.0.msi" }
  }
}
```
updater 优先读取此清单，回退到 GitHub API 直接解析 release assets。

### 五、GitHub Actions 流水线

**新增 `.github/workflows/release.yml`**：
- 触发：push tag `v*` + 手动触发
- 三个并行 job（matrix: macos-latest, ubuntu-latest, windows-latest）：
  - **macOS**：`cargo build --release`（universal: aarch64 + x86_64），`cargo-bundle` → `.app`，`hdiutil` → `.dmg`
  - **Linux**：`cargo build --release`，`cargo-deb` → `.deb`，tarball 打包
  - **Windows**：`cargo build --release`，`cargo-wix` → `.msi`，zip 打包
  - 每个 job 上传 artifact
- **release job**（依赖三个构建 job）：
  - 下载所有 artifacts
  - 生成 `latest.json` 更新清单
  - 创建 GitHub Release（softprops/action-gh-release），附加所有平台 artifacts + `latest.json`

**新增 `.github/workflows/ci.yml`**：
- 触发：push to main, PR
- 三平台并行 `cargo build` + `cargo test`

### 七、更新检查流程

1. **自动**：App 启动后 3 秒静默异步检查 → 有新版本仅标题栏按钮亮红点
2. **手动**（标题栏按钮 / 设置页按钮）：点击 → loading 旋转 → 完成后：
   - 有更新 → 标题栏按钮变下载图标 + 设置页显示版本详情 + 「前往下载」按钮
   - 无更新 → Notification 提示「当前已是最新版本」+ 设置页显示 ✓
   - 失败 → Notification 提示错误信息
3. 下载 → 打开浏览器到 release 页面，用户选择对应平台安装包
