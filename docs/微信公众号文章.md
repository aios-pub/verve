## 🎯 开发者的实际痛点

API 开发过程中，通常需要在多个工具间频繁切换：

- **API 调试工具**（如 Postman）发送测试请求
- **终端工具**（如 iTerm2）SSH 连接服务器查看日志
- **文档工具**（如 Swagger）生成和分享 API 文档
- **版本控制**（Git）管理 API 定义的变更

这种多工具协作模式存在明显问题：

| 问题 | 影响 |
|------|------|
| 🔀 **频繁切换** | 上下文切换成本高，打断工作流 |
| 📊 **信息分散** | API 定义、测试结果、服务器状态在不同工具中 |
| 🔄 **同步困难** | 文档更新滞后，版本管理混乱 |
| 💰 **成本高昂** | 多个专业工具的订阅费用累积 |

## 🚀 Verve：用 Rust + GPUI 一体化解决

### 什么是 Verve？

**Verve** 是一款用 **Rust + GPUI** 构建的桌面应用，**在一个窗口内集成**了：

- 📡 **HTTP 调试** — 完整的 API 调试能力
- 🔐 **SSH 终端** — 多标签服务器管理
- 📄 **文档分享** — 一键生成和分享 API 文档
- 🌍 **Git 版本控制** — 自动保存和协作

**一个工具，替代 Postman + 终端 + 文档工具。**

### 为什么是 Rust + GPUI？

| 技术选择 | 为什么重要？ |
|---------|-------------|
| **Rust** | 零成本抽象，内存安全，并发性能强 |

| **一体化集成** | 不再是多个工具拼凑，而是原生集成体验 |

**GPUI 是什么？**

GPUI 是 Zed 编辑器（号称"性能最好的代码编辑器"）使用的 UI 框架。Verve 是**极少数采用 GPUI 的生产级应用**之一，这意味着：

## 💡 一体化集成的工作流程

### API 调试与服务器排查的无缝衔接

在后端 API 开发中，调试请求失败时通常需要查看服务器日志。传统工作流需要在不同应用间切换：

```
API 工具（Postman） → 发现问题 → ⌘Tab → 终端（iTerm）→ SSH 服务器 → 查日志 → ⌘Tab → API 工具
```

**Verve 的集成方案：**

在单一窗口内同时提供：
- 左侧面板：HTTP 调试界面，发送测试请求
- 右侧面板：SSH 终端标签页，连接服务器查看日志

调试过程中发现问题，无需切换应用，直接在右侧终端查看服务器状态、检查日志、数据库状态。问题定位后，返回左侧修改请求参数并重试。

### 从 API 定义到文档分享的完整流程

API 文档生成和分享通常涉及多个工具和步骤：

```
API 定义工具（Postman）→ 导出数据 → 文档生成工具（Swagger）→ 部署服务 → 分享链接
```

**Verve 的工作流：**

1. 在 Verve 中完善 API 定义（请求方法、参数、响应结构）
2. 右键点击项目/文件夹/单个请求，选择"生成文档"
3. 选择分享方式：
   - **二维码分享**：手机扫码直接访问
   - **链接分享**：设置过期时间，发送链接
   - **HTML 导出**：生成独立 HTML 文件

**企业级访问控制特性：**
- ⏰ **过期时间**：1小时/1天/1周/永久，自动失效
- 🔐 **密码保护**：服务器端强制验证
- 🌐 **云端部署**：内置 verve-server，支持 Docker 部署

### 多服务器统一管理

管理多台服务器时，传统方式需要打开多个终端窗口：

```
生产服务器（窗口1）| 测试服务器（窗口2）| 数据库（窗口3）| Redis（窗口4）| 堡垒机（窗口5）
```

**Verve 的多标签终端：**

在单一窗口内通过标签页管理多台服务器连接：

```
┌─────────────────────────────────────┐
│ [生产] [测试] [数据库] [Redis] [堡垒] │
├─────────────────────────────────────┤
│ $ tail -f /var/log/app.log          │
└─────────────────────────────────────┘
```

标签页持久化保存，断线自动重连，支持堡垒机跳板连接。

**SSH 终端特性：**
- 🔑 多种认证：密码/私钥/SSH Agent
- 🎨 ANSI 彩色：16色/256色/真彩色
- 🔄 自动重连：指数退避策略
- 🛡️ 堡垒机支持：ProxyJump 跳板
- 🔒 安全存储：系统钥匙串 + 加密

## 🎯 核心功能深度解析

### 1️⃣ HTTP 调试：完整且智能

**支持的能力：**
```
✓ 所有 HTTP 方法：GET/POST/PUT/DELETE/PATCH/HEAD/OPTIONS
✓ 所有请求体类型：form-data / x-www-form-urlencoded / raw(JSON/XML/Text/HTML/JS)
✓ 智能变量替换：{{variable}} 支持多级作用域
✓ 脚本支持：前置脚本 & 测试脚本（JavaScript）
✓ 完整响应面板：状态/时间/大小/请求头/响应体/JSON 美化
```

**变量继承链：**
```
全局变量
    ↓
环境变量
    ↓
文件夹变量
    ↓
请求变量

示例：
base_url = "https://api.example.com"  （全局）
token = "{{env_token}}"               （环境）
user_id = "12345"                      （请求）

最终请求：GET {{base_url}}/users/{{user_id}}?token={{token}}
```

**一次配置，处处可用！**

### 2️⃣ SSH 终端：专业级服务器管理

**典型使用场景：**

在单一窗口内通过标签页管理多台服务器：

```bash
标签1：ssh production           → 生产环境日志查看
标签2：ssh staging              → 测试环境配置管理
标签3：ssh bastion → ssh db     → 通过跳板机连接数据库
标签4：ssh redis                → 缓存状态检查
```

左侧面板进行 API 调试，右侧面板管理多个 SSH 连接。调试过程中发现问题时，直接在终端查看日志、检查服务状态、修改配置，无需切换到其他应用。

**企业级特性：**
- 🔄 自动重连：断线无需手动重连
- 🛡️ 堡垒机：支持企业跳板机架构
- 🔒 安全存储：敏感信息加密存储
- 📑 会话管理：标签页持久化

### 3️⃣ 文档分享：协作零障碍

**从 API 定义到可分享文档：**

```
1. 右键点击项目/文件夹/单个请求
2. 选择"生成文档"
3. 选择分享方式：
   📱 二维码分享（手机扫码访问）
   🔗 链接分享（设置过期时间）
   📄 HTML 导出（生成文件）
```

**访问控制：**
- ⏰ 过期时间：防止长期泄露
- 🔐 密码保护：服务器强制验证
- 🌐 云端部署：verve-server 支持 Docker

**verve-server 管理面板：**
```bash
verve-server --port 8080
# 访问 http://your-server:8080/admin
# 查看所有文档、访问统计、权限管理
```

### 4️⃣ Git 版本控制：自动化协作

**每个工作区 = 一个 Git 分支**

```
main         → 生产环境 API
├── feature-a  → 功能 A 开发中
├── feature-b  → 功能 B 开发中
└── hotfix     → 紧急修复

**Verve 的工作方式：**
- 创建新工作区 = 创建新 Git 分支
- 每 30 分钟自动提交并同步更改
- 切换工作区时，API 定义自动切换
- 每个工作区的配置独立存储

```
