# 笔记双链与图谱视图迭代计划

> 状态：**待决策**（未实现）。本文档为后续开发的蓝图与决策参考。
> 前置基础：笔记已改造为「每条一个 `.md` 文件 + YAML frontmatter」存储（见 `src/notes.rs`）。本计划在此之上叠加双链（`[[wiki-link]]`）与图谱视图。
> 行号基于 2026-08 当前代码，后续可能漂移，**以函数名/接入点描述为准**。

---

## 一、背景

笔记存储已从单 JSON 文件改为「每条笔记一个 `.md` 文件」（`~/.verve/notes/`，参考 Obsidian/Logseq）。这是实现双链与图谱视图的**必要基础**——所有主流笔记软件的双链都建立在文件存储之上。

本计划在此基础上加入：
- **双链（backlinks）**：`[[笔记标题]]` 语法 + 反向链接 + 编辑器内补全与可点击跳转
- **图谱视图（graph view）**：力导向布局，笔记为节点、双链为边

链接目标采用**标题（可读）**形式，重命名笔记时**自动更新所有引用**（用户已确认）。

---

## 二、主流开源项目调研结论

### 双链（backlinks）—— 四家做法高度一致

核心都是 `[[wiki-link]]` 语法 + 扫描构建链接索引 + 转置求反向：

| 项目 | 链接语法 | 索引方式 |
|---|---|---|
| Obsidian | `[[笔记名]]`、`[[笔记名\|别名]]`、`[[笔记名#标题]]` | `metadataCache.resolvedLinks`：`{源文件: {目标文件: 链接计数}}`，backlinks 是它的**转置** |
| Logseq | `[[页面]]`、`#标签`、块引用 `((块id))` | 块级图索引（Datalog 查询），更细粒度 |
| Foam | `[[文件名]]`、`[[文件名\|别名]]` | 扫描 .md 生成 Markdown reference definitions，graph 从磁盘内容派生 |
| SilverBullet | `[[页面]]` | 扫描 frontmatter + 正文 wikilinks 建索引 |

**关键机制**（参考 Obsidian `MetadataCache.resolvedLinks`）：
1. 扫描每个文件的 `[[...]]` → 得到**前向链接**（A → B）
2. **反向链接 = 前向链接的转置**（谁引用了我）
3. 文件变更时增量重解析（Verve 已有 `notify` watcher，可直接复用）
4. 编辑器层：CodeMirror 用装饰把 `[[...]]` 实时渲染成可点击链接，输入 `[[` 弹出笔记名补全

### Graph view

节点 = 笔记、边 = 链接关系、节点大小 = 入度（被引用次数），用**力导向布局**（节点互斥 + 边吸引 → 收敛平衡），Canvas/WebGL 渲染、可拖拽缩放。

### Rust 生态（对 Verve 的 GPUI 架构）

- **petgraph**：图数据结构（成熟）。Verve 可不引入，节点/边用 `HashMap`/`Vec` 足够
- **fdg**：纯 Rust 力导向布局库。可不用——自实现简化 Fruchterman-Reingold（~100 行）即可覆盖笔记量级（几十~几百节点）
- **渲染**：Verve 是 GPUI（自绘），不能用 visgraph（导出图片）。需用布局算坐标 + GPUI `canvas`/`paint_quad` 绘制

## 三、总体架构

1. 新增一个**链接索引层**作为 L1/L2/L3 的共用基础
2. 编辑器通过**回调注入**（而非硬编码 notes 逻辑）获取补全候选与处理 wikilink 打开，保持其通用性（Editor 不只用于 notes）
3. 图谱视图作为 **NotesPanel 内部子视图**（复用 store/侧栏，改动最小）

## 四、核心数据层：链接索引（L1/L2/L3 共用）

### 新建 `src/notes/links.rs`（notes 拆出 links 子模块）

```rust
/// 一个 wikilink 引用（从正文扫描得到）。
pub struct WikilinkRef {
    pub target: String,               // 目标标题（规范化前）
    pub heading: Option<String>,      // [[target#heading]]
    pub alias: Option<String>,        // [[target|alias]]
}

/// 扫描 markdown 正文里的 [[...]]，跳过 fenced code / HTML 块 / 转义。
/// 仿 wysiwyg/components/markdown/link.rs::parse_link_reference_definitions 骨架。
pub fn scan_wikilinks(content: &str) -> Vec<WikilinkRef>

/// 笔记间的链接关系索引。
pub struct NoteLinkIndex {
    by_title: HashMap<String, Vec<String>>,         // 规范化 title → note id 列表（title 可重名）
    outlinks: HashMap<String, Vec<WikilinkRef>>,    // source id → 出链
}

impl NoteLinkIndex {
    pub fn build(store: &NotesStore) -> Self;       // 全量构建
    pub fn resolve(&self, target: &str) -> Option<&str>;  // 标题→id（重名取 created_at 最早）
    pub fn outlinks(&self, id: &str) -> &[WikilinkRef];
    pub fn inlinks<'a>(&'a self, id: &str, store: &'a NotesStore)
        -> Vec<(&'a Note, Vec<&'a WikilinkRef>)>;   // 转置求反向
}
```

### 设计要点
- **title 规范化**：复用 `wysiwyg/components/markdown/image.rs::normalize_reference_label`（大小写折叠 + 空白归一），保证 `[[foo bar]]` 命中 title 为 `Foo Bar` 的笔记
- **重名处理**：`sanitize_filename` 只保证文件名不冲突，title 本身允许重复 → `by_title` 用 `Vec<id>`；`resolve` 取 `created_at` 最早（确定、可预测）
- **扫描器**：手写行扫描器（符合项目风格，不用 regex/pulldown-cmark 建索引），必须跳过 fenced code / HTML 块 / 转义，可直接复用 `link.rs` 的 fence/HTML 检测函数（`parse_reference_scan_opening_fence` 等）
- **索引更新时机**：NotesPanel 加字段 `link_index: NoteLinkIndex` + `rebuild_link_index()`，在 store 变更后（select/save/new/delete/toggle/move）重建。笔记量级小，全量重建简单可靠

### 单元测试
- 扫描器：中文标题、`[[a|别名]]`、`[[a#heading]]`、代码块内不索引、转义、嵌套括号
- 索引：构建、resolve（含重名歧义）、inlinks 转置正确性

- **点击跳转**：当前点击流程 `RequestOpenLink → pending_open_link → render.rs:718 cx.open_url` 只处理 URL。新增**回调注入**：

  - `render.rs:718` 检测 `InlineLink::Wikilink` → 调回调而非 `open_url`

### 阶段 3：L2c —— `[[` 自动补全弹窗（工作量最大）
**从零构建触发式补全弹窗**（编辑器无现成触发式弹窗基础设施）。

改动：
- Editor 加字段 `wikilink_completion: Option<CompletionState { query, candidates, selected, anchor_pos }>`
- **触发**：`replace_text_in_visible_range`（runtime/mod.rs:1838）后，检测光标前未闭合的 `[[` → 提取 query
- **候选来源**：Editor 加回调 `wikilink_provider: Option<Arc<dyn Fn(&str) -> Vec<String> + Send + Sync>>`，notes_panel 注入（返回匹配标题列表）
- **弹窗 UI**：参考 `editor/context_menu.rs` 的浮动菜单渲染，锚定光标位置（用 `interactions.rs:1565` 的光标几何）
- **键路由**：新建独立 key context（仿 `actions.rs:240` 的 `FIND_BAR_CONTEXT`），处理 ↑/↓/Enter/Esc

验证：输入 `[[` 弹候选列表，↑↓ 选择，Enter 插入

### 阶段 4：L3 —— 力导向图谱视图（独立大功能）
改动：
- notes_panel 加 `graph_mode: bool` + 图谱状态（`node_pos: HashMap<id,(f32,f32)>`、`zoom: f32`、`pan: (f32,f32)`、`dragging: Option<id>`）
- titlebar（`app/titlebar.rs:1191` 紧挨 view-mode 按钮）加「图谱」切换按钮 → toggle `graph_mode`；Render（行 1637）按 `graph_mode` 选 `render_editor` / `render_graph`
- **布局算法**：新建 `src/ui/graph_layout.rs`，**自实现简化 Fruchterman-Reingold**（节点互斥 + 边吸引 + 温度退火，~100 行），**零新依赖**。坐标预算好存实体字段
- **渲染**：`canvas(prepaint, paint)`
  - prepaint：记录每个节点 `Bounds`（坐标×zoom+pan）到 `RefCell<HashMap>`
  - paint：`window.paint_quad` 画节点（圆角矩形）+ 画边（细 `paint_quad` 或 `svg().path()`）
  - 节点文字：绝对定位 `div` 叠加在 canvas 上（避免自己 paint glyph，文字渲染质量更好）
- **交互**：`on_scroll_wheel`（Ctrl 缩放）、`on_drag(NoteDrag(id))/on_drop`（节点拖拽，仿 rail.rs:222）、画布 pan（拖空白）、点击节点命中（`bounds.contains`）→ `select_note`
- 数据：节点 = `store.notes`，边 = `link_index.outlinks` resolved 到 id

验证：切到图谱视图，看到节点与连线，可缩放/拖拽节点/点击跳转

## 六、关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 链接扫描方式 | 手写行扫描器 | 符合项目风格（link.rs 模板），能正确跳过代码块/HTML/转义 |
| title 规范化 | 复用 `normalize_reference_label` | 大小写折叠 + 空白归一，`[[foo bar]]` 命中 `Foo Bar` |
| 重名解析 | 取 created_at 最早 | 简单确定；歧义可在 UI 标注 |
| 编辑器解耦 | 回调注入（`on_open_wikilink`/`wikilink_provider`） | Editor 保持通用，不硬编码 notes 逻辑 |
| 图谱布局 | 自实现 Fruchterman-Reingold | 零新依赖，节点量级小，可控 |
| 图谱视图位置 | NotesPanel 内部子视图（路线 A） | 复用 store/侧栏，改动最小 |
| 图谱节点文字 | 绝对定位 div 叠加 canvas | 避免自绘 glyph，文字渲染质量好 |
| 链接标识 | 标题（可读）+ 重命名更新引用 | 人类可读，符合 Obsidian 习惯；重命名时全局扫描替换 |

## 八、风险与缓解

- **L2 改编辑器**：wysiwyg 是移植自 velotype 的复杂代码。改 `InlineLink` 枚举 + 解析 + 序列化需保证 markdown 往返——阶段 2 配套单元测试（`[[x]]` 往返、与现有 `[label](url)` 共存、嵌套场景）。每阶段独立交付 + 验证，降低回归面。
- **L2c 补全弹窗键路由**：GPUI 键上下文隔离需谨慎，严格仿 `FIND_BAR_CONTEXT` 模式；弹窗激活时拦截方向键，Esc 退出还原焦点。
- **重命名更新引用**：全局扫描替换所有 .md，量级可控；替换仅改 `[[旧标题...]]` 内的目标段，保留别名/heading 后缀；title 规范化匹配，避免大小写/空格差异导致漏替换。
- **图谱性能**：paint 闭包每帧重画，力导向布局必须在闭包外（实体字段）预算好坐标，paint 只读取绘制，避免在 paint 里跑物理模拟。

---

## 九、编码规范（遵循 AGENTS.md）

- 扫描器用 `char_indices` / 字节偏移在 `\n` 边界操作，禁裸字节切片
- 索引一律 `.get(i)`
- 生产代码禁 `unwrap()`（resolve 失败返回 `None` 静默跳过）
- UI 回调入口校验索引在界内
- 原子写入（`.tmp` + `rename`），重命名引用更新时逐条 `save_note` 落盘
